## 2. Git：怎么理解，怎么用

### 2.1 三棵树

```
工作区 (working tree)  →  暂存区 (index/stage)  →  提交链 (commits)
   你眼前看到的文件          下一次提交的货物清单        只追加的快照历史
        git add ────────────────┘        git commit ─────┘
```

### 2.2 三个认知（记住这三条，Git 就不神秘）

1. **提交是快照，不是 diff。** 每个 commit 存的是整棵树的完整状态，diff 是两次提交"比"出来的，不是存下来的。
2. **分支只是一个指针。** `main` 就是指向某个提交的可移动标签；`HEAD` 指向"我现在在哪个分支上"。切分支 = 移动指针 + 换文件。
3. **能回退，是因为历史只追加、不会消失。** 只要你 commit 过，就能找回来；没 commit 的改动才是真危险。

### 2.3 日常 8 条

```bash
git status                 # 我在哪、改了什么（每次先跑这个）
git diff                   # 未暂存的改动，逐行看
git add -A                 # 全部放进暂存区（或 git add 文件名 精确添加）
git commit -m "docs: 说明"  # 生成一个快照
git log --oneline -10      # 最近 10 个提交，一行一个
git diff HEAD~1            # 和上一个提交比（看"这次到底改了什么"）
git show <hash>            # 某个提交的完整内容
git restore <文件>          # 丢弃未提交的改动（危险：不可恢复）
```

### 2.4 回滚三板斧

| 想干什么 | 命令 | 后果 |
|---|---|---|
| 撤掉还没 add 的改动 | `git restore <文件>` | 工作区回到上次提交，改动丢失 |
| 撤掉已 add、未 commit | `git restore --staged <文件>` | 退回工作区，改动还在 |
| 已经 commit 但想撤回 | `git revert <hash>` | 新增一个"反向提交"，历史保留，**安全** |
| 把整个分支退到某提交 | `git reset --hard <hash>` | 该提交之后的提交从分支上消失（reflog 里还能捞） |

**默认用 `revert`，不用 `reset --hard`**：前者只加不减，后者容易把自己坑了。

## 3. GitHub 上的"插件"能不能用

### 3.1 先分清三种东西

| 常被叫"插件"的东西 | 实际形态 | DSH 能否直接用 |
|---|---|---|
| DSH 插件 | cordis 插件，npm 包（`@deepseek-ai/dsh-*`） | 能，改 profile 的 `package.json` + 重启 |
| **MCP server** | 独立进程，走 stdio/JSON-RPC | **能**（见下）——GitHub 上 90% 的"插件"是这类 |
| GitHub Actions | 云端 CI，与本地无关 | 与本机沙箱无关，不涉及 |

### 3.2 实测证据：MCP 是一等公民

在 DSH 的 `app.asar` 里扫到并确认存在：

- `@deepseek-ai/dsh-mcp-client` —— MCP 客户端插件
- `@deepseek-ai/dsh-mcp-resources` —— MCP 资源接入
- 实验性：`dsh-experimental-browser-use-chrome-devtools-mcp`、`-playwright-mcp`、`dsh-experimental-computer-use-cua-driver-mcp`
- 配置键 `mcpServers`（202 处引用）、client 方法 `mcp_connect`

所以：**GitHub 上带 mcp 的 server（stdio 型）理论上都能接**，包括浏览器控制、数据库、搜索、文件系统这类。

### 3.3 网络现实（本次实测）

| 探测 | 结果 | 含义 |
|---|---|---|
| TCP `github.com:443` | ✅ 通 | 裸机网络本身没被墙 |
| 沙箱内 HTTPS | ❌ TLS 握手失败 | 沙箱拦的是 TLS 层，不是 DNS/TCP |
| 沙箱内 HTTP | ⚠️ 301 → https，跟随即失败 | 走不了 HTTP 降级 |
| 系统代理 | `127.0.0.1:7890` 存在，但 `ProxyEnable=0` | 装了 Clash 类工具，未启用 |

**结论**：
- **不需要 VPN 来解决"能不能连"** —— 裸 TCP 是通的，是否需要代理取决于直连速度和稳定性。
- **VPN 也解决不了沙箱内的拦截** —— 那得申请一次 `danger-full-access`，只对"安装那一次"生效。
- 装插件的最小流程：`npm install` / `git clone` 提权一次 → 文件落地后日常使用不再需要网络。

### 3.4 推荐流程（挑一个 MCP server 试）

1. 在 GitHub 找 stdio 型 MCP server（有 npm 包优先，`npx -y <包名>` 就能跑）
2. 说明用途 → 申请一次完整权限，`npm install` 或 `git clone`
3. 在 `C:\Users\mazix\.dsh\profiles\desktop\` 里注册（`package.json` 的 `dependencies`，或 `cordis.patch.yml` 加一条 entry）
4. 重启 DSH，在 GUI 里确认新工具出现
