## 三个新发现

### 1. `tools/` 是老对象，缺沙箱授权 → 只能读不能写

- 现象：`python -m venv tools\venv` 报 `WinError 5 拒绝访问`；`icacls tools` 里**没有** `S-1-4-…` 与 `Low Mandatory Level`，而 `data/ notes/ projects/ tmp/` 都有。
- 原因：老规矩——授权晚于建目录，已存在的子目录不回填（见上一份记录第 2 坑）。
- 处置：venv 放到工作台根 `.venv`（根目录有授权，可写）；`tools/` 不动。
- 想根治：需要跑一次 ACL 修复脚本（要一次完整权限，见"待办"）。

### 2. 沙箱里 `ensurepip` 会失败，pip 要手工装

- 现象：`python -m venv` 报 `ensurepip returned non-zero`，venv 建好但没有 pip；把 `TEMP` 指到工作区后，又卡在 `tempfile` 清理时的 `chmod` 被拒。
- 原因：ensurepip 要在临时目录里 `chmod 0700` 再删除，沙箱 token 没有这项权限。
- 解法（可复用）：把自带 wheel 直接解压进 venv 的 site-packages。

```powershell
$whl = 'C:\Users\mazix\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\Lib\ensurepip\_bundled\pip-25.0.1-py3-none-any.whl'
$sp  = 'C:\Users\mazix\work\.venv\Lib\site-packages'
Add-Type -AssemblyName System.IO.Compression.FileSystem
[System.IO.Compression.ZipFile]::ExtractToDirectory($whl, $sp)
```

注意：这样装出来的 pip **没有 `pip.exe`**，一律用 `.venv\Scripts\python.exe -m pip`。

### 3. `~/.gitconfig` 在工作区外，写不了

- 现象：`git config --global user.name` 报 `could not lock config file C:/Users/mazix/.gitconfig: Permission denied`。
- 结论：这不是 ACL 问题，是沙箱边界（工作区外禁止写）。仓库级配置正常生效。
- 影响：本仓库提交没问题；**换新目录 / 新建仓库时身份会丢**，需要在你自己终端里跑一次：

```powershell
git config --global user.name  "你的名字"
git config --global user.email "你的邮箱"
```
