## 发现并修复

### 1. `check-env.ps1` 的 `-c` 引号 bug（会报假 FAIL）

PowerShell 5.1 给原生程序传参时会剥掉参数里的双引号，`python -c 'print("pip", ...)'` 到 python 手里变成 `print(pip, ...)` → `SyntaxError`。

- 修法：`-c` 代码里**不写任何引号**（用 `import ... as p` 和纯空格 print）。
- 回归：11/11 PASS。

### 2. `.venv` 只有 pip、没有核心库（开工必炸的最大隐患）

原 venv 是隔离环境，`import numpy` 直接 `ModuleNotFoundError`。系统 Python 自带 numpy/pandas/openpyxl/docx/pptx/Pillow/lxml/xlsxwriter，但 venv 看不见。

- 修法：`pyvenv.cfg` 打开 `include-system-site-packages = true`。
- 注意：`python -m venv --system-site-packages` 的**参数在沙箱里会被剥掉**（重建后 cfg 记录里没有这个 flag），所以直接改 cfg 才可靠。
- 回归：用 venv 生成 xlsx/docx fixtures，跑通 recalculate + render 整条链。

### 3. `new-project.ps1` 身份无兜底

原逻辑无条件继承工作台配置；万一全局配置缺失，`git commit` 会直接失败。现在缺失时兜底 `mazix / mazix@local`，冒烟通过。

### 4. `check-env.ps1` 失败时退出码仍是 0

机器判断会误以为通过。已加 `exit $fail`（失败项数即退出码）。

### 5. `new-project.ps1` 没有版本控制

`tools/` 整体被 `.gitignore` 忽略，脚手架脚本一直没入库，丢了没备份。修复：改为 `tools/*` + `!tools/new-project.ps1`，脚本已入库（`git ls-files` 可查）。

### 6. 每次 `git add` 刷 CRLF 警告

`.gitattributes` 对 `.ps1/.cmd` 声明 `eol=crlf`，与 DSH 文件工具写的 LF 冲突，每次 add 都警告。修复：工作区全部文本统一 `eol=lf`（Windows 的 PowerShell/cmd 都兼容 LF），`add --renormalize` 后零警告。
